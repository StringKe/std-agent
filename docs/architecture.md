# 架构与模块划分

## 1. 总体架构

```
        +-----------+      +----------+
 user ->| stdagent  |----->| transfor |---> CLAUDE.md / AGENTS.md / .claude/ / ...
        |   CLI     |      |   mers   |
        +-----+-----+      +----+-----+
              |                 ^
              v                 |
        +-----------+    +------+------+
        | config /  |    | std-files   |
        | state mgr |    | parser      |
        +-----------+    +------+------+
              |                 ^
              v                 |
        +------------+   +------+------+
        | git source |-->| .stdai/cache|
        |   sync     |   |  /standards |
        +------------+   +-------------+
```

## 3. 转换器 interface

```go
type Transformer interface {
    Name() string                                    // "claude-code" 等
    Plan(docs []*parser.Document, cfg *config.Config) (*Plan, error)
    Apply(plan *Plan, w *writer.Writer) error
}

type Plan struct {
    Files []FileOp
}

type FileOp struct {
    Path     string                                  // 相对项目根
    Content  []byte
    Mode     fs.FileMode
    Marker   bool                                    // 是否注入 stdagent marker
    Skip     bool                                    // 与现有文件一致时跳过
    Reason   string                                  // 诊断
}
```

每个 target 的 transformer 独立文件，互不依赖。

## 4. 数据流

```
sync 命令:

1. config.Load(.stdai/config.toml)
2. source.Fetch(cfg) 
     -> git pull (auto_pull=true)
     -> 收集 .stdai/standards/ + cache/<src>/<paths>
3. parser.ParseAll(files)
     -> 校验 frontmatter
     -> 产出 []Document
4. for each enabled target:
     -> transformer.Plan(docs, cfg)
5. canonicalize shared AGENTS.md + collision check
6. 若 gitignore != off：UpsertGitignore（dry-run 只比较）
7. for each plan:
     -> backup.Snapshot(plan.Files)
     -> writer.Apply(plan, footer)
8. state.Save(outputs, checksums, last_sync)
9. report.Print(plans)
```

dry-run 模式：只做 Plan + gitignore 比较 + diff，不 Apply 也不 Snapshot。

## 5. 关键决策

### 5.1 选 cobra 而非 urfave/cli

- 子命令树深度可能扩展（`stdagent target list/add/...`）
- shell 补全自动生成
- 与生态多数 Go CLI 一致

### 5.2 选 go-toml/v2 而非 BurntSushi/toml

- v2 性能更高、错误信息更友好
- 支持 `omitempty` 等现代 marshal 选项

### 5.3 选 go-git/v5 而非 shell out 到 git

- 嵌入 binary 即可工作，无需用户预装 git
- 跨平台一致行为
- 取舍：体积约 +6MB；MVP 接受

### 5.4 选 yaml.v3 而非 yaml.v2

- 保留键顺序、更准确的错误位置
- 已成事实标准

### 5.5 frontmatter 解析

实现策略：

```go
func splitFrontmatter(b []byte) (front []byte, body []byte, ok bool)
```

要求：

- 文件以 `---\n` 开始
- 找到下一个 `---\n` 或 EOF
- 起始之间的 byte 为 front；之后为 body
- 起始 `---` 之前必须为空（允许 BOM）

### 5.6 transformer 注册

```go
// internal/transformer/registry.go
var transformers = map[string]Transformer{
    "claude-code": &ClaudeCode{},
    "codex":       &Codex{},
    // ...
}
```

新增 target = 实现 interface + 在 registry 注册。

### 5.7 marker 检测

每个生成文件首/尾的 HTML 注释作为 marker：

```html
<!-- Generated by stdagent vX.Y.Z. Do not edit by hand. -->
...
<!-- /Generated by stdagent -->
```

`writer.Apply` 写入前：

1. 若文件不存在 -> 直接写
2. 若文件存在且含 marker -> 备份后覆盖
3. 若文件存在但无 marker -> 备份后覆盖 + WARN（用户手写覆盖）

JSON / TOML 文件不能用 HTML 注释。改用：

- TOML: `# Generated by stdagent` 顶行注释
- JSON: 整个对象包一个 `_stdagent_marker` 顶层字段（值为版本字符串）；
  下游工具忽略未识别字段
- JSONC: 顶部 `// Generated by stdagent` 注释（Cursor/VSCode mcp.json 接受 JSONC）

v1.0 仅 .md 落盘，无 JSON/TOML 写入压力，留 v1.1。

## 6. 性能目标

- 解析 100 个 std 文件 < 200 ms
- 9 target 全部 transform < 800 ms
- 写盘 27 文件 < 500 ms
- 总体 p95 < 2 s（小项目）/ < 5 s（大项目）

## 7. 错误处理原则

- 校验错误：明确 file path + line + 字段，整体中止
- IO 错误：尝试回滚（恢复 backup），写 stderr，退出码 1
- 远端 pull 失败：保留 cache 旧版本，WARN，sync 继续（除非 `--strict`）
- transformer panic：捕获后 stderr 报告 + skip 该 target，其他 target 继续

## 8. 测试策略

- `internal/parser/`: golden file（fixtures/std/*.md -> 期望 struct）
- `internal/transformer/<target>/`: golden file（input docs -> 期望 output 文件树）
- `cmd/stdagent`: integration test 用 testscript
- 跨平台：CI 矩阵 ubuntu/macos/windows
